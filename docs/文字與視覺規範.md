# 文字與視覺規範

> 來源：[決定紀錄.md](決定紀錄.md)「文字簡化與視覺化」（使用者 2026-11-17）。
> 本文件的數字都由測試對照程式常數，常數改了而這裡沒改，測試會失敗；不要手寫別處已有的數字。

## 一、文字

| 規則 | 內容 | 誰把關 |
|---|---|---|
| 單句長度 | 畫面文字單一句超過 40 字就不允許新增或變長；現有超長句列在基準檔，只准減不准增 | `tests/text-scan.mjs` 的 `MAX_SENTENCE_LEN`、`tests/long-text.test.mjs`、基準 `tests/long-text-baseline.json` |
| 掃描範圍 | `shared/app.js`、`index.html` 內的中文字串 | `tests/text-scan.mjs` 的 `FILES` |
| 區塊寫法 | 每區塊先給一行結論，再給一個數字或進度條；細節收進折疊 | 人工審查（預覽連結＋ 390px 檢查） |
| 長說明的編排 | 一律用 `app.js` 的 `foldNotes(id, 標題, 短句清單)`（內部用 `noteLines`），不要再手寫一長段文字 | `tests/long-text.test.mjs` |
| 低注意力讀者 | 以「懶散、資深、只看 5 秒的金融從業者」為底線：折疊標題要一眼看懂、每個折疊行數有上限，關鍵結論與數字不放進折疊 | `tests/long-text.test.mjs` 的折疊說明測試（標題與行數上限在該檔常數）；結論不放進折疊靠人工審查 |
| 最少操作與思考 | 紅隊要問：使用者要點幾下、要記什麼、要自己算什麼？能由程式預設、自動帶入、自動算出的，不讓人選、不讓人填、不讓人算；一個畫面一個主要動作 | 人工審查（PR 紅隊段逐項回答）；能機械判斷的再補測試 |
| 語氣 | 第二人稱、結論先行、數字具體、不催促 | 人工審查 |
| 數字來源 | 制度與官方數字只寫在 `shared/reference-data.js`；畫面、文件都不得抄寫 | `tests/core.test.mjs` 的單一權威來源測試（含 `.md`） |

降低長句的作法：把句子拆短，或改成「一行結論＋折疊」，改完用 `node tests/text-scan.mjs --write-baseline` 更新基準（基準只會變少）。

## 二、資料量與長期使用

- 帳本逐筆、各期比較、核對紀錄預設只列近 3 個月；更舊的按年月折疊（`Money.splitRecentMonths`）。
- 新增任何會隨時間變長的清單，都要走同一個函式，並在 `tests/recent-months.test.mjs` 補測試。
- 折疊狀態用既有的 `data-collapse-id`，不新增存檔欄位。

## 三、視覺

- 字體：以襯線為主（`--serif`）。
- 顏色：以單一強調色（`--accent` 系列）為主；語意色只用在錯誤或不足（`.neg`）；同一畫面輔助色最多一處；不用圖示。
- 對比：文字對背景先算過再用，一般文字至少 4.5:1；一律用 `shared/style.css` 的變數，不在元件裡寫死色碼。
- 數字：金額與比例用等寬字（`.mono`）。
- 動態：安靜；使用者設定減少動態時要關閉。
- 比較：同組屬性跨多個項目時用表格，不用一長串文字。
- 手機：以 390px 寬檢查；表格不能靠橫向捲動才看得到關鍵欄位，必要時把次要資訊放進第一欄的小字。

## 四、改動時的流程

1. 先看本文件與 [決定紀錄.md](決定紀錄.md)，確認沒有違反使用者已做的決定。
2. 動工前跑一次 `node tests/text-scan.mjs`，看現有超長句。
3. 改完用真實存檔複本在 390px 實際看過，再開 PR，並附未合併預覽連結。
4. 新的使用者決定寫進 [決定紀錄.md](決定紀錄.md)，規則本身寫在本文件，不要兩邊各寫一份。
